# 安全说明

本工具会修改 Windows 的网络配置数据库。以下是它的安全边界和实测验证记录。

## 一、安全模型

### 只动被确证过的手机配置

一个网络配置**只有在它的网关 MAC 于真实网络共享会话中被记录过**，才会被本工具操作。

这意味着：

- 你的 WiFi、有线网络配置**永远不是候选对象**
- 即使某个网络的 MAC "看起来像随机生成的"，也不会被碰
- 判定依据是**实际观察**，不是猜测

> 开发过程中确实用过"MAC 看起来随机"这个启发式，结果误判了两个真实网络（某些路由器本来就使用本地管理位 MAC）。已彻底移除。

### 正在使用的配置永远不会被删除

这是**硬规则，双重检查**：

1. 每轮运行先记录本次在线（`Get-NetConnectionProfile`）的配置 GUID 列表
2. 清理阶段对每个待删配置再查一次：在列表里 → 跳过

### 判断不出"哪个在线"时，拒绝删除

新增的硬联锁：

```
若（本次没有识别到任何在线配置）
    则 跳过整个清理阶段，只记一条调试日志
```

这覆盖两种危险情形：

- `-MergeOnly` 模式（该模式本就不做设备识别）
- 适配器已出现但 Windows 还没分配配置

在这两种状态下删除配置，正是"可能删掉正在使用的配置"的路径，所以直接不做。

### 清理前一定备份

任何清理动作之前，都会 `reg export` 完整导出网络配置数据库到 `backup\`：

```
backup\Profiles-<标签>-<时间戳>.reg
backup\Signatures-<标签>-<时间戳>.reg
```

用 `reg import` 可完整还原。

### 不装驱动、不做系统级 hook

- **无服务**
- **无驱动**
- **无常驻进程**
- 只注册**一个计划任务**（以 SYSTEM 身份运行，这是修改 `HKLM` 所必需的）

任务设置中 `WakeToRun=false`，所以**不会唤醒睡眠中的电脑**；`ExecutionTimeLimit=PT5M` 保证不会卡住；`StartWhenFinished` 相关的电池限制全部关闭，笔记本用电池时也能正常工作。

## 二、实测验证记录

| 验证项 | 结果 |
|---|---|
| 改名是否立即生效 | ✅ 不需要重启任何服务，设置界面立刻显示新名字 |
| 删除 + 备份还原闭环 | ✅ 删除配置后可从 `.reg` 完整还原 |
| 真实 WiFi 是否被误改 | ✅ 5 个原配置经过数百次会话始终未被操作 |
| 重启后是否恢复 | ✅ 开机 33 秒后任务自动执行，`result=0x0` |
| 多台手机并用 | ✅ 三台手机各自独立命名，配置总数稳定不增长 |
| 名字被改坏能否自愈 | ✅ 手动改成「网络 99」后，下次运行自动改回 |
| `state.json` 有界性 | ✅ 模拟 100 次会话后指纹列表稳定在上限 |
| 无手机时的开销 | ✅ 0.52 秒退出，不写任何日志 |
| 非管理员运行 | ✅ 礼貌提示需要权限，不崩溃 |

### 关于"重启后是否可靠"

事件触发器依赖三个服务，均为**自动启动**（已核实）：

| 服务 | 状态 | 启动类型 |
|---|---|---|
| `EventLog` | Running | Automatic |
| `EventSystem` | Running | Automatic |
| `Schedule` | Running | Automatic |

两个事件日志通道（`Microsoft-Windows-Kernel-PnP/Configuration`、`Microsoft-Windows-NetworkProfile/Operational`）均处于启用状态。

此外还有**开机触发（延迟 30 秒）+ 每日一次**双保险，`StartWhenAvailable=true`（错过的运行会补跑）。

### 对开关机的影响

| 项目 | 值 | 含义 |
|---|---|---|
| `WakeToRun` | False | 不会唤醒睡眠中的电脑 |
| `ExecutionTimeLimit` | PT5M | 最多运行 5 分钟（实际 1~10 秒）|
| `DisallowStartIfOnBatteries` | False | 电池供电时也工作 |
| `StopIfGoingOnBatteries` | False | 切到电池不会中断 |
| `MultipleInstancesPolicy` | IgnoreNew | 不会并发运行 |
| 常驻进程 | 无 | 进程只活 1~2 秒 |

## 三、回滚

### 恢复网络配置数据库

```powershell
# 管理员权限的 PowerShell
$dir = Join-Path $env:UsbNetFixHome 'backup'   # 或你的实际安装目录
reg import (Join-Path $dir 'Profiles-<时间戳>.reg')
reg import (Join-Path $dir 'Signatures-<时间戳>.reg')
```

### 卸载

```powershell
.\UsbNetFix.cmd uninstall        # 交互式，会问是否清理残留配置
.\uninstall.ps1 -Purge           # 连程序文件一起删除
.\uninstall.ps1 -CleanProfiles   # 静默清理残留的手机配置（保留最新一个）
```

卸载脚本会：

1. 停止并注销所有相关计划任务
2. 结束正在运行的实例（只匹配命令行含 `usbnet-fix.ps1` 的进程）
3. 询问是否清理手机残留配置（**会先备份**）
4. 保留程序目录（除非加 `-Purge`）

### 手工彻底恢复

如果想完全回到初始状态：

```powershell
# 1. 删除计划任务
Unregister-ScheduledTask -TaskName 'UsbNetFix-OnPhonePlug' -Confirm:$false

# 2. 删除程序目录
Remove-Item (Join-Path $env:UsbNetFixHome) -Recurse -Force

# 3. 若想连网络配置一起重置（注意：这会清空所有保存的 WiFi！）
#    Settings > Network & Internet > Advanced network settings > Network reset
```

> ⚠️ 第 3 步是 Windows 自带的"网络重置"，它会**删除你所有保存的 WiFi 密码**。这正是本项目想要避免的操作，除非万不得已不要用——用上面的 `.reg` 还原更安全。

## 四、需要注意的边界

1. **本工具需要管理员权限**，因为网络配置数据库位于 `HKLM`。计划任务以 SYSTEM 身份运行即为此目的。

2. **它修改的是 Windows 自己的数据库**，与"清理注册表"类工具性质不同：改动范围严格限制在 `NetworkList\Profiles` 和 `NetworkList\Signatures` 两个键之下。

3. **不会碰你的 WiFi 密码**。WiFi 凭据存在另外的位置（`ProgramData\Microsoft\Wlansvc`），本工具从不读写那里。

4. **日志和 state.json 含设备信息**（手机型号、USB 序列号）。如果你要把日志发到公开场合（如提 issue），请先检查内容——`verify-release.ps1` 也正是为此而做。

5. **首次使用的新手机可能显示默认名**，这不算故障：安卓只在「传输文件」模式上报型号名，连一次即可记住。
