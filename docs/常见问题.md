# 常见问题与故障排查

## 一、使用问题

### 双击 UsbNetFix.cmd 弹出了 UAC，正常吗？

**正常，这是设计如此。**

`HKLM\...\NetworkList` 这个注册表键的属主是 SYSTEM，ACL 里只有两条规则：`BUILTIN\Administrators` 完全控制、`NETWORK SERVICE\netprofm` 可读写。**标准用户连读都不允许**——不弹 UAC 的话，控制面板里几乎所有菜单都只能显示"需要管理员权限"。

所以启动器会主动请求提权。如果你点了"否"，它会退化为普通权限继续运行（信息类命令仍可用）。

> 日常插手机**完全不需要任何交互**：后台计划任务以 SYSTEM 运行。

### 插上手机后名字没变？

按顺序检查：

1. **控制面板里选 `3 monitor`** —— 确认电脑确实认到了手机的网卡（应显示 `Remote NDIS` 之类的适配器）
   - 没显示 → 手机上的 USB 网络共享没打开，或数据线只支持充电
2. **选 `2 names`** —— 看工具认出了什么、打算叫什么名字
   - 如果显示 `usb model: (phone never reported a model)`，说明这台手机还没在「传输文件」模式下连过电脑
3. **选 `1 status`** —— 看计划任务状态
   - `not registered` → 选 `5` 重新安装
   - `Ready` 但 `result` 不是 `0x0` → 看 `log\usbnet-fix.log` 的最后几行

### 名字是 `USB Tethering` 而不是手机型号？

这台手机还没上报过型号名。安卓只在**「传输文件」(MTP) 模式**下上报自己的市场名，而网络共享和传输文件在安卓上是**互斥**的两种 USB 配置。

**解决办法**：把手机的 USB 用途切成「传输文件」，等电脑识别出手机存储，然后再切回「USB 网络共享」。工具会记住型号，之后就一直用型号名了。

### 为什么手机名后面有个「 2」？

说明这个基础名字已经被**另一台手机**占用了。工具不允许两台手机同名（同名会被当成彼此的旧残留清理掉）。

对策：给每台手机在 `config.json` 里配一条 `DeviceRules`，指定不同的名字。

### 插着手机时无法传输文件？

这是**安卓的限制，不是本工具造成的**，两者在 USB 层面互斥：

| 手机的 USB 用途 | 产品 ID | Windows 看到的接口 |
|---|---|---|
| **USB 网络共享** | `PID_600A` | 只有 `MI_00` = RNDIS 网卡 |
| **传输文件 (MTP)** | `PID_6012` | `MI_00` = MTP，`MI_01` = 大容量存储 |

安卓一次只启用**一种** USB 配置，所以开着共享时 MTP 接口根本没被枚举出来。

变通办法（从易到难）：

1. **无线传输** —— 微信/QQ 文件助手、LocalSend、Feem，共享保持开着
2. **切换 USB 用途** —— 切成「传输文件」拷完再切回来（网络会断几秒）
3. **`adb push` / `adb pull`** —— USB 调试是另一个接口，可以与共享共存，但需要驱动且比 MTP 慢
4. **云盘中转**

### 会不会把我的 WiFi 弄丢？

**不会。** 本工具只操作**被确证过来自手机**的网络配置——判定依据是"该配置的网关 MAC 在网络共享会话中被实际观察过"。你的 WiFi 配置从来不是候选对象。

这一点经过实测：5 个真实 WiFi 配置在数百次会话中从未被改动。

### 会不会影响开关机速度？

**不会。**

- 无常驻进程（进程只活 1~2 秒）
- 无服务、无驱动
- 任务设置 `WakeToRun=false`，不会唤醒睡眠中的电脑
- 开机触发延迟 30 秒，避开开机最繁忙的阶段

### 占多少资源？

空闲时**完全为零**（事件驱动，没有轮询）。事件触发时约 0.5~10 秒，峰值内存约 180 MB（PowerShell 解释器基线，退出即释放）。

## 二、故障排查

### 收集诊断信息

```
UsbNetFix.cmd diagnose
```

会在 `log\` 下生成一份完整快照（设备信息、指纹、网络配置列表、任务状态、日志尾部）。

> ⚠️ **这份文件包含你的手机型号和 USB 序列号。** 要发到公开场合（如 GitHub issue）前，请先检查并删掉这些内容。

### 提示找不到 netprof-lib.ps1 之类的文件

说明程序目录**不完整**（少文件了）。重新把整个文件夹完整拷一遍即可。

程序支持两种布局：**平铺**（所有 `.ps1` 在同一层，发布包解压后就是这样）和 **`lib\` 子目录**。两种都能自动识别，但文件不能缺。

### 任务存在但什么都没发生

检查任务的**动作路径是否真实存在**：

```powershell
$a = (Get-ScheduledTask -TaskName 'UsbNetFix-OnPhonePlug').Actions[0].Arguments
$a
Test-Path '<安装目录>\usbnet-fix.ps1'   # 把路径换成上面输出里的实际路径
```

开发过程中遇到过这个坑：**任务确实被触发了、也确实"成功"了，但 `-File` 指向了一个没有脚本的目录**，于是什么都没发生。所以现在注册任务时会打印实际 runner 路径。

如果路径不对：重新运行 `UsbNetFix.cmd` → 选 `5`。

### 手动跑一次看报错

```powershell
# 管理员 PowerShell，路径换成你的安装目录
cd <安装目录>
powershell -ExecutionPolicy Bypass -File .\usbnet-fix.ps1 -Once
```

- `-Once` 跳过 8 秒等待，立即执行
- `-DryRun` 只报告会改什么，**不做任何修改**
- `-MergeOnly` 只清理已知手机的残留
- `-Loop` 常驻轮询（调试用，正常情况不需要）

> 若在 `lib\` 布局下，路径是 `.\lib\usbnet-fix.ps1`。

### 自检

```
verify.bat
```

会跑 7 项检查：脚本语法、纯 ASCII 编码、个人信息残留、运行时数据、配置 JSON 有效性、**入口点真实运行**、以及最终复扫清理。任何一项失败都会明确报出来。

### 日志在哪

```
<安装目录>\log\usbnet-fix.log
<安装目录>\log\diag-*.txt       诊断快照
<安装目录>\log\tasks.txt        任务注册记录
```

日志超过 768 KB 会自动轮转，旧诊断快照也会按数量/天数自动清理。

## 三、开发踩坑记录

这些都是真实花掉过时间的坑，列出来免得别人重复。

| 坑 | 症状 | 解决 |
|---|---|---|
| `Profiles\{GUID}` 里**没有** `Signature` 值 | 整条查找链静默失效，"0 改动" | 关联方向是反的：`Signatures\*\ProfileGuid` 指向配置 |
| 把 `DateCreated` 当 FILETIME | 日期解析为空 | 它是 16 字节 `SYSTEMTIME`（8 个小端 WORD）|
| 相信"MAC 看起来像随机" | 真实路由器也用本地管理位 MAC，会误改用户的 WiFi | 只操作真实手机会话中确证过的指纹 |
| `reg.exe export` 不带 hive 前缀 | 备份静默产生 0 个文件 | 必须写成 `HKLM\...` |
| PS 5.1 按 ANSI 解析无 BOM 的 `.ps1` | 脚本里含非 ASCII 时解析失败（字符串里的 `$var:`、未终止的字符串）| 脚本保持纯 ASCII，非 ASCII 内容放到 JSON |
| 提权进程里用 `Global\` 互斥体 | 「访问被拒绝」，单实例保护静默失效 | 改用 `Local\` 命名空间 |
| 用字符串推导父设备名 | 形如 `6&1EB7303F&1&0000` 的接口实例上失效 | 直接问设备树（`DEVPKEY_Device_Parent`）|
| 把 USB 接口实例最后一段当序列号 | 那其实是**端口路径**，换个插口就变 | 序列号要从父设备取 |
| 用 USB 端口区分手机 | 同一个口上两台手机会解析成同一个型号 | 用 USB 序列号做身份主键 |
| 用 CIM 对象注册事件触发器 | `Register-ScheduledTask` 报"成功"但任务不存在 | 用原始 XML 定义任务 |
| 事件查询里用 `EventData` 过滤 | `The specified query is invalid` | 只支持等值比较，改在脚本里过滤 |
| `config.json` 里的空字符串 | `"LogFile": ""` 被当成有效路径 → 日志静默丢失 | 空串视为"未配置"，并加回退路径 |
| `.cmd` 存成 UTF-8 | cmd.exe 按 ANSI 解析，吃掉换行，每个词都变成命令 | `.cmd` 存成 ANSI/ASCII |
| 手工复制文件同步 | 旧版覆盖新版；任务指向空目录（`0xFFFD0000` 静默失败）| 用单向的 `deploy.ps1`，校验哈希并打印 runner 路径 |
| 每分钟轮询 | 1440 次/天，全是空转 | 改为 USB / 网络配置事件 + 开机 + 每日兜底 |
| 没插手机也先等 8 秒 | 绝大多数运行都在浪费时间 | 先做预检查，没手机就立即退出 |
| 验证脚本会运行工具本身 | 工具写出的日志里含手机真实型号和序列号 | 把测试的日志定向到临时目录，测完复扫全目录 |
| **只支持 `lib\` 布局** | 发布包是平铺的，控制面板一启动就报"找不到 netprof-lib.ps1"，**每个命令都失败** | 运行时探测实际布局；验证脚本同时检查退出码和输出内容 |
| **验证脚本只检查退出码** | 上面那个布局 bug 被漏报，因为报错后退出码仍是 0 | 改为同时检查退出码、输出内容、以及有无"命令未找到"字样 |
| 辅助脚本里写中文 | PS 5.1 按 ANSI 解析无 BOM 脚本，中文把解析器搞崩 | 连一次性的辅助脚本也保持纯 ASCII |

### 关于编码

Windows PowerShell 5.1 会把**无 BOM 的 `.ps1` 按 ANSI（中文系统是 GBK）解析**。这导致过：

- `.ps1` 里的中文注释把解析器搞崩（报"字符串缺少终止符"）
- `.cmd` 文件里的 UTF-8 中文把换行吃掉，导致 `'l' 不是内部或外部命令`

**本项目所有脚本保持纯 ASCII**，中文只出现在 `.md` 和 `.json` 里。`verify-release.ps1` 的第 2 项检查就是在守这条规则。

## 四、反馈问题

提 issue 时请附上：

1. **诊断快照**（先自行删除手机型号和序列号）
2. Windows 版本（`winver`）
3. 手机型号与安卓版本
4. 你期望的行为 vs 实际行为

如果方便，把 `log\usbnet-fix.log` 的最后 30 行也贴上（同样注意清理敏感内容）。
